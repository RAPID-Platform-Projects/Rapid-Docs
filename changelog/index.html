v1.67 — Rapid Platform

September 21, 2026 · 3 min read
Danny Rattu
Documents

We're excited to announce new features live on Rapid Platform Monday, September 28th

Features​

Permission inheritance​

Items can now inherit their permissions from a parent record. In Designer, the Permission Inheritance section of a table's Security & Permissions tab lets you choose the parent using a lookup or universal link column, and system lists and tables that extend another table can inherit too. New items take on their parent's permissions when they're created, and any change to the parent's permissions flows down through every level of child items. You can also choose whether a table's items share its default permissions or have their own, and restore a record to its table's default inheritance at any time.

Permissions admin page​

A new Permissions admin page under Maintenance in Designer shows which items have permissions that differ from their table's defaults. From here you can reset items to their defaults, bulk apply permissions to items matching a filter, or bulk set items to inherit from their parent. Every bulk change is previewed before it's applied. You can also see exactly who can access an item and where that access comes from, or pick a user or group to see everything they can access.

SharePoint permission sync in the background​

SharePoint permissions now sync in the background whenever an item is created or updated, so saving is no longer slowed down by the sync. Folder permissions follow the same inheritance as their items, and drift is detected and repaired automatically. Admins can track queued, completed and failed syncs in the new Permission Sync Events list.

Stronger Designer and Workflow permissions​

The Designer and Workflow permissions are now enforced across the API, not just in the UI. Any user, integration or AI agent without the Designer permission can no longer change a site's structure, such as its tables, fields, views, menus and pages, and workflow administration requires the Workflow permission. Tables that extend another table are now protected by their own permissions, so a user with access to a base table can't read the extra fields on a table they haven't been granted.

Improvements​

  • You'll now see a confirmation, showing where an item's permissions come from, before breaking its permission inheritance
  • Permission errors from Designer and Workflow are now shown instead of failing silently
  • Searching in the principal picker is no longer case-sensitive
  • Full principal names are now shown in the permission picker and table
  • You can no longer save an empty set of permissions
  • Pages now show an empty state when none of their tabs are visible to you
  • Installing a bundle now checks its tables first and names any invalid table, instead of installing it partially

Bug Fixes​

  • Fixed an issue where notes created from the Activity Feed didn't inherit permissions from the record they were linked to
  • Fixed an issue where removing a table that extends another table failed with a SQL error
  • Fixed an issue where submitting a long public form could fail
  • Fixed an issue where public forms failed to load on sites containing a table installed from a bundle without settings
  • Fixed an issue where pages failed to load when their search state contained a dot
  • Fixed an issue where the Creating document notification in Adaptive Designer never cleared

v1.64 — Rapid Platform

June 23, 2026 · 2 min read
Danny Rattu
Documents

We're excited to announce new features live on Rapid Platform Tuesday, June 23rd

Features​

Experiences are now Workspaces​

Experiences have been renamed to Workspaces throughout the platform, including labels, routes and search. You can now link a menu item to a Workspace, which displays that Workspace's full menu as nested children. Any changes made to the linked Workspace's menu are reflected automatically, without needing to re-save the menu that links to it.

Tab permissions​

You can now limit which tabs in a Tab Strip are visible to specific users or groups. Tabs a user doesn't have access to are hidden when they view the page, while all tabs remain visible when editing the Tab Strip in Designer.

Wait for all Inclusive Gateway paths​

Inclusive Gateways in Workflow can now wait for the outcomes of all active paths before the process continues. This is useful for scenarios such as onboarding, where a user may be provisioned to several systems and the process can't proceed until every system has been provisioned.

Application principals​

We've added a new principal type for applications. Application principals respect permissions in the same way as users and groups, so integrations can be given only the access they need.

Improvements​

  • Added a New View button to the menu in Designer
  • Added an Open in Adaptive Designer button to User Tasks in Workflow
  • Creating a new table now lets you choose whether it's added to the sidebar menu
  • The Get Rapid Item service task now shows a clear error when the target list or item can't be found
  • Links in the External Page component that open a new tab or navigate the parent page now work

Bug Fixes​

  • Fixed an issue where CSV exports could be missing rows
  • Fixed an issue where copying an expression from a labelled Workflow element copied the label instead of the reference
  • Fixed an issue where deleting a condition watcher in Adaptive Designer left its expression behind
  • Fixed an issue where cascading lookups crashed the page when the linked list had no title field
  • Fixed an issue where large uploads failed because of a field size limit
  • Fixed an issue where document introspection in DocX templates stopped working
  • Addressed styling issues with the public form URL in the state menu

1.60.0 - Rapid Platform

January 5, 2026 · 2 min read
Joshua Nauer
Documents

Release Date: 05/01/26

Features​

Map Location Fields​

We would like to introduce a new field type for Rapid lists, Geography. These fields can store the Latitude and Longitude of a location.

Adding the fields to a page will now present the map location stored. Clicking a location will set it as required.

For the report writers out there, these are stored as Geography fields using WKT POINT format. For those of you interested in getting these points into PowerBI you will need to cast them for the built-in Map visual. For example:

SELECT id
 ,title
 ,CAST(geo_field.Lat as FLOAT) 'Lat', CAST(geo_field.Long as FLOAT) 'Long'
FROM dbo.geo_list

Improvements​

  • Creating a new process via upload will now pre-fill the title
  • Altering permissions on items now requires at minimum edit permission to perform
  • Permissions synced to SharePoint will now expand the groups and create individual permissions where required
  • Updated Support chat-bot to new long-term model for better speed

Bug Fixes​

  • Execute workflow menu actions that contain inputs with a lookup to the current item will no longer crash on submission
  • Recovered Ctrl+Enter shortcut to submit Activity Feeds notes, as it was just adding a new line before
  • Support chat bot can answer your queries again

1.57.0 - Rapid Platform

November 10, 2025 · One min read
Joshua Nauer
Documents

Release Date: 10/11/25

We're excited to announce new features live on Rapid Platform Monday November 10th!

Split values to choice and radio controls in Adaptive​

We've introduced the ability to assign split values to adaptive radio buttons and choices, enabling users to define a value that differs from the displayed label. This is particularly useful in scenarios where descriptive labels are used for user input, but numerical values are needed for backend processing or analysis. Users can now click the link icon when editing a choice or radio option to separate the label from its value, allowing them to store meaningful data directly without relying on post-submission conversion.

Improvements

  • Enhanced the adaptive Rich Text Editor for better usability and formatting support.
  • Updated permission handling when assigning placeholder permission fields via API or workflow.

Bug Fixes

  • Fixed a crash that occurred when attempting to extend a non-existent list.
  • Resolved an error triggered by the timer under certain conditions.
  • Addressed styling inconsistencies in adaptive components.
